# DevLog — T-201.3: Sales Form Pickers + UX Polish

## Session Header
- **Date:** 2026-06-01
- **Type:** Feature implementation
- **Focus:** Frontend — sales module UX polish
- **Status:** Complete

### Objective
Fix four issues surfaced during Quote-form testing:
1. Currency field is a free-text input — needs constrained dropdown
2. Payment Terms is free-text — needs typeahead picker against `payment_terms` master
3. Exchange Rate always visible — should only show when currency != tenant base
4. SalesItemCombobox (and CustomerCombobox) dropdown clipped by table-cell overflow

---

## What We Accomplished

### Deliverable 1 — CurrencyCombobox (`components/sales/CurrencyCombobox.tsx`)
- 11-currency constrained dropdown: AED, BHD, EUR, GBP, INR, KWD, OMR, PKR, QAR, SAR, USD
- Tenant base currency (read from `useFinanceCompanies` → first row's `defaultCurrency`)
  floats to top with "Base — recommended" section header and blue "Base" badge
- Remaining currencies sorted alphabetically under "Other currencies" divider
- Props: `value`, `onChange`, `disabled`, `hasError`, `describedBy`
- Styled-components with `$hasError`, `$disabled`, `$open` transient props (UI-Standards.md)
- ARIA: `role="combobox"` + `role="listbox"`, keyboard ↓/↑/Enter/Esc/Space

### Deliverable 2 — PaymentTermsCombobox (`components/sales/PaymentTermsCombobox.tsx`)
- Typeahead picker over `payment_terms` master via `usePaymentTerms` hook
- Reuses the same hook purchasing's PR/PO forms use — shared data source, shared cache
- `PaymentTerms` type from `purchasingApi.ts`: `{ termsId, termsCode, description, netDays }`
- Chip state when selected (shows description + "Net N" badge); search input when unselected
- `onChange` receives `PaymentTermsSelection | null` with termsId UUID, description, netDays
- Filters client-side on description, termsCode, and netDays string

### Deliverable 3 — useTenantBaseCurrency (`hooks/queries/useTenantBaseCurrency.ts`)
- 15-line hook reading `useFinanceCompanies(orgId)` → `companies[0].defaultCurrency`
- Falls back to `'AED'` when not yet loaded or no companies configured
- Single source of truth across all 8 sales forms for base-currency comparisons

### Exchange Rate Conditional Visibility (wired in each form)
- `showExchangeRate = watch('currency') !== baseCurrency`
- Field wrapped in `{showExchangeRate && (...)}` — disappears when currency matches base
- `useEffect` resets `exchangeRate` to `1` whenever `showExchangeRate` becomes false
- Submit payload always includes a valid `exchangeRate` (never undefined/null)

### Deliverable 4 — Portal Fix (`SalesItemCombobox.tsx` + `CustomerCombobox.tsx`)
- Root cause: dropdown `position: absolute` is clipped by `overflow: hidden` on ancestor `<td>`
- Fix: `createPortal(dropdown, document.body)` + `position: fixed`
- Position computed via `wrapperRef.getBoundingClientRect()` in `useLayoutEffect`
- Auto-recalculated on `window scroll` (capture phase) and `window resize`
- Flip logic: if not enough space below, opens above the trigger instead
- Click-outside handler extended to check both `wrapperRef` and the portaled `document.getElementById(listboxId)` panel
- z-index: `9999` — floats above entire page layout

## Important Context for Next Session

- All sales form pages now import `useTenantBaseCurrency` — this hook calls `useFinanceCompanies`
  which requires a valid `orgId`. If the user is not logged in or the org has no finance company
  configured, it falls back gracefully to `'AED'`.
- The portal approach for SalesItemCombobox/CustomerCombobox means the dropdown panel is NOT inside
  the form DOM — click-outside detection explicitly checks `document.getElementById(listboxId)`.
- ArCreditNoteFormPage now has a PaymentTermsCombobox in the header (was in schema, never rendered).
  The schema field `paymentTermsId` was already being submitted to the backend; this just surfaces it in UI.
