# DevLog — T-200.11: Legacy /sales/orders + /sales/returns Cutover

**Date:** 2026-05-31
**Session type:** Feature cutover / deletion
**Focus area:** Wave 3 Sales Module closeout
**Status:** Complete

---

## 1. Session Header

**Objective:** Remove the legacy `SalesOrdersPage` and `ReturnsPage` (and all
associated components, service functions, and types that only served those pages),
add redirects for `/sales/orders` → `/sales/orders-v2` and `/sales/returns` →
`/sales/returns-v2`, and remove the legacy backend routes (`orders.py`,
`returns.py`). This is the final task in Wave 3 Sales Module.

---

## 2. What We Accomplished

### Pre-work audit (grepped before touching any code)
- Confirmed sidebar already clean — `MainLayout.tsx` only has `/sales/orders-v2` and
  `/sales/returns-v2` entries. No legacy entries found.
- Confirmed `SalesDashboardPage` uses `salesApi.getDashboardStats()` which calls
  `/v1/sales/dashboard` (NOT the legacy orders endpoint). Safe to keep.
- Confirmed `salesService.ts` is used only by `SalesDashboardPage` (for
  `getDashboardStats`, `formatDate`) after the legacy pages are removed.
- Confirmed `DeleteOrderConfirmModal` had no consumers other than `SalesOrdersPage`.
- Confirmed `OrderCard` has no consumers at all (dead code).
- Confirmed backend tests (211) do not reference the legacy routes at all.
- Confirmed `dashboard.store.ts` only had a metadata string reference to the
  legacy endpoint (not an API call).

### Frontend changes

**Files deleted (5,990 + 316 = 6,306 total lines removed):**
- `pages/sales/SalesOrdersPage.tsx` — 566 lines
- `pages/sales/ReturnsPage.tsx` — 584 lines
- `components/sales/OrderTable.tsx` — 374 lines
- `components/sales/OrderForm.tsx` — 853 lines

- `components/sales/ReportReturnModal.tsx` — 836 lines
- `components/sales/DeleteOrderConfirmModal.tsx` — 571 lines
- `components/sales/OrderCard.tsx` — 316 lines (dead code, no consumers)

**Files modified:**
- `App.tsx` — removed `SalesOrdersPage` + `ReturnsPage` lazy imports; replaced their
  routes with `<Navigate to="/sales/orders-v2" replace />` and
  `<Navigate to="/sales/returns-v2" replace />`
- `services/salesService.ts` — stripped legacy order/return CRUD functions (kept
  `getDashboardStats`, `getAvailableFarmingYears`, utility helpers, `salesApi` export)
- `types/sales.ts` — removed `SalesOrderCreate`, `SalesOrderUpdate`,
  `SalesOrderSearchParams`, `PaginatedSalesOrders`, and all legacy return types
  (`ReturnReason`, `ReturnCondition`, `ReturnStatus`, `ReturnItem`, `ReturnOrder`,
  `ReturnOrderCreate`, `PaginatedReturns`). Kept `SalesOrder` and its shape
  dependencies since `SalesDashboardStats.recentOrders` still references it.
- `hooks/queries/useSales.ts` — removed `useSalesOrders` and `useSalesOrder`
  (called the now-removed `salesApi.getSalesOrders/getSalesOrder`); kept
  `useSalesDashboard`
- `hooks/queries/index.ts` — removed exports for `useSalesOrders`, `useSalesOrder`
- `stores/dashboard.store.ts` — updated metadata string from `/api/v1/sales/orders`
  to `/api/v1/sales/orders-v2`

### Backend changes

- `src/modules/sales/api/v1/__init__.py` — removed `orders_router` and
  `returns_router` imports and `api_router.include_router()` calls. The files
  `orders.py` and `returns.py` remain on disk (not deleted) in case of rollback, but
  are no longer registered. Added module-level docstring explaining the cutover.

### SalesDashboard "Recent Orders" navigate link
The `SalesDashboardPage` still navigates to `/sales/orders/${order.orderId}` when
a recent-order row is clicked. With the redirect in place, this goes to
`/sales/orders-v2` (the list, not a specific detail) since legacy `orderId` strings
do not map to Wave 3 `docEntry` integers. This is acceptable — the redirect is clean
and the dashboard widget is cosmetically functional. A follow-up (if desired) would
update the dashboard to use Wave 3 order data.
