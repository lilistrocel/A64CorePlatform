## 1. Session Objective

Fix production error: `HTTP 500: cannot encode object: datetime.date(2026, 5, 30), of type: <class 'datetime.date'>`.

PyMongo / Motor cannot encode bare `datetime.date` objects — only `datetime.datetime`. All five Wave 3 sales services were storing Pydantic `date` fields directly into MongoDB writes. Task scope was AR Invoice + Credit Note; SO, Delivery, and Quote were fixed in the same session to unblock the full smoke chain.

---

## 2. What We Accomplished

### Root Cause Identified
Pydantic models for Wave 3 sales documents use `date` type for date fields (correct for API validation). When these values flow into `insert_one` / `update_one` document dicts, they are passed as bare `datetime.date` — which Motor cannot serialize to BSON. PyMongo only accepts `datetime.datetime`.

### Fix Pattern: `_to_dt()` Helper
Added identical `_to_dt(d: date) -> datetime` helper to all five service files:

```python
def _to_dt(d: date) -> datetime:
    if isinstance(d, datetime):
        if d.tzinfo is None:
            return d.replace(tzinfo=timezone.utc)
        return d
    return datetime(d.year, d.month, d.day, 0, 0, 0, tzinfo=timezone.utc)
```

Converts at midnight UTC so the calendar date is preserved unambiguously regardless of reader timezone.
