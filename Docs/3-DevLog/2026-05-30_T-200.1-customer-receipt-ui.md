## Bugs Discovered and Fixed

### Bug 1: Backend 500 — "cannot encode object: datetime.date(2026, 5, 30)"

- **Severity:** Critical (blocker — no receipt could be created)
- **File:** `src/modules/sales/services/customer_receipt_service.py`
- **Root cause:** `payload.doc_date` is Pydantic-parsed as Python `datetime.date`. PyMongo/Motor requires `datetime.datetime` with timezone for BSON serialization. `datetime.date` is not a supported BSON type and raises at the Motor encode step.
- **Fix:** Added `_to_dt()` helper (identical to `ar_invoice_service.py`). Applied on both the insert path and the update path (guarded with `if payload.doc_date is not None`).

### Bug 2: `ARInvoiceDetailPage.tsx` — wrong CUSTOMER_RECEIPT route in docTypeRoute

- **Severity:** Medium (doc-chain links on ARI detail page navigated to non-existent route)
- **File:** `frontend/user-portal/src/pages/sales/ARInvoiceDetailPage.tsx`, `docTypeRoute()` helper
- **Fix:** Changed `return '/sales/receipts/${docEntry}'` → `return '/sales/customer-receipts/${docEntry}'`.
