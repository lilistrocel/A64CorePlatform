## What was built

### AccountCombobox extension (drawer + type hints)

`frontend/user-portal/src/components/finance/AccountCombobox.tsx`

- Imported `DRAWER_LABELS` and `ACCOUNT_TYPE_LABELS` from `financeAccountsService`
- Added `DrawerTypeBadge` styled component (neutral pill)
- Every dropdown option now renders: `124000-001 — Trade Receivables Customers` +
  `[Assets · asset]` badge so users can immediately confirm they are picking the right
  kind of GL account without leaving the combobox

### PostingSetupPage hardening

`frontend/user-portal/src/pages/finance/PostingSetupPage.tsx`

1. **AR Control and Output VAT now required** — both were previously optional in the UI
   (no `*` marker, no client-side validation). These two accounts are gating for the
   AR Invoice posting flow (`sales_invoice_posted` handler). Added:
   - `required` prop to both `AccountSelect` components
   - Both fields included in the `isFormComplete` derived bool
   - Both fields included in the `clientErrors` pre-save validation block
2. **Client-side pre-save validation** — validates all 7 required fields before hitting
   the backend; sets field-level errors inline and shows a banner; returns early so the
   network call is never made for incomplete saves
3. **Field hints** — `hint` prop added to `AccountSelect` sub-component; all 10 fields
   have descriptive hints explaining the accounting event they participate in
4. **ESLint cleanup** — removed two unnecessary `eslint-disable-next-line` directives
   that had become stale when the hooks deps were simplified

Required fields after this change:
- `apControlAccountId` — AP Invoice Cr (purchasing)
- `arControlAccountId` — AR Invoice Dr (sales) ← NEW required
- `bankAccountId` — payments
- `grIrClearingAccountId` — GR/IR clearing (purchasing)
- `inputVatAccountId` — Input VAT (purchasing)
- `outputVatAccountId` — Output VAT Cr (sales) ← NEW required
- `retainedEarningsAccountId` — period-close

### Route alias

`frontend/user-portal/src/App.tsx` — `/sales/posting-setup` routes to the same
`PostingSetupPage` component (wrapped in `FinanceGate`), giving sales admins a
direct path from the Sales nav group without navigating through Finance.

### Sidebar entry

`frontend/user-portal/src/components/layout/MainLayout.tsx` — "Posting Setup" added
at the bottom of `SALES_NAV_GROUP` after "Sales Items Config", with route
`/sales/posting-setup` and the `🗂️` icon (matching the Finance nav entry).
