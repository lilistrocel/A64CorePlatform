## 2. What We Accomplished

### Backend

**New file: `src/modules/sales/models/reports.py`**
- `ARAgingCustomerRow` — one (customer, currency) group with five bucket amounts + invoice_count
- `ARAgingGrandTotals` — cross-customer sums + customer_count + invoice_count
- `ARAgingReport` — top-level: asOfDate + customers list + grandTotals
- `ARAgingParams` — internal query param DTO
- All response models use `_RESPONSE_CONFIG` imported from `ar_invoices.py` (camelCase alias generator, populate_by_name, from_attributes)

**New file: `src/modules/sales/services/reports_service.py`**
- `compute_ar_aging(db, org_id, *, customer_id, as_of_date, currency)` — Python loop approach
- Fetches only outstanding invoices (`status in ['open', 'partly_closed']`)
- Uses `totals.openAmount` directly (already net of paidAmount + creditedAmount)
- Bucket assignment: `daysOverdue = (as_of_date - dueDate).days`; buckets: current (≤0) / 1-30 / 31-60 / 61-90 / over90
- Groups by `(customerId, customerName, currency)` using defaultdict
- All amounts quantized to 2dp via `Decimal.quantize(Decimal('0.01'), ROUND_HALF_UP)`
- Sorted: descending total, then ascending customer_name

**New file: `src/modules/sales/api/v1/reports.py`**
- `GET /ar-aging` — `require_permission("sales.view")`, `response_model_by_alias=True`
- Resolves org_id from query param or JWT claim
- Defaults `as_of_date` to today UTC if not supplied

**Modified: `src/modules/sales/api/v1/__init__.py`**
- Imported `reports_router` and registered at prefix `/reports`
- Full path: `/api/v1/sales/reports/ar-aging`

**New file: `src/modules/sales/tests/test_ar_aging.py`**
- 6 test scenarios: empty org, one invoice per bucket, multi-currency, customer filter, skip non-outstanding statuses, decimal precision
- All 6 pass. Full sales suite: 211 passed (up from 205 baseline).

### Live smoke
