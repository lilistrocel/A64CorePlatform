## Backend hardening (pre-flight required)

**Problem:** ARC models in `ar_credit_notes.py` lacked `_RESPONSE_CONFIG` and routes lacked `response_model_by_alias=True`. All field names were being serialized as snake_case, breaking the frontend camelCase contract.

**Fix:**
- Added `_RESPONSE_CONFIG = ConfigDict(populate_by_name=True, alias_generator=to_camel, from_attributes=True)` to `ar_credit_notes.py`.
- Applied `model_config = _RESPONSE_CONFIG` to all five response models: `CreditNoteAllocationResponse`, `CreditNoteLineResponse`, `CreditNoteTotals`, `ARCreditNoteResponse`, `ARCreditNoteListItem`.
- Added `response_model_by_alias=True` to all six route decorators in `ar_credit_notes.py`.
- Restarted API container and verified live: all levels (top-level, totals, lines, allocations) return camelCase.

**Smoke result:**
- `ARC-2026-0001` returns `docEntry`, `docNumber`, `customerName`, `status` (camelCase) at top-level.
- `totals` keys: `net`, `tax`, `gross` (camelCase).
- `lines[0]` keys: `lineId`, `lineNumber`, `creditedQty`, `unitPrice`, `lineNet`, `lineTax`, `lineGross` (camelCase).
- `allocations[0]` keys: `allocationLineNumber`, `arInvoiceDocEntry`, `arInvoiceDocNumber`, `amountApplied` (camelCase).

## Four hardening rules confirmation

1. **Path constant** — `ARC_BASE = '/v1/sales/ar-credit-notes'` (no `/api/` prefix; apiClient adds that). File: `frontend/user-portal/src/services/salesApi.ts`.
2. **`_RESPONSE_CONFIG` on all response models** — Applied to `CreditNoteAllocationResponse`, `CreditNoteLineResponse`, `CreditNoteTotals`, `ARCreditNoteResponse`, `ARCreditNoteListItem`. File: `src/modules/sales/models/ar_credit_notes.py`.
3. **`response_model_by_alias=True` on all routes** — All 6 decorators (GET list, GET detail, POST create, PATCH update, DELETE, POST transition). File: `src/modules/sales/api/v1/ar_credit_notes.py`.
4. **Status literals lowercase** — `'draft' | 'open' | 'partly_closed' | 'closed' | 'cancelled'` throughout. `ARCreditNoteStatus` type in `salesApi.ts`.
