# DevLog — T-201.2: SalesItemCombobox + wire into all 8 sales doc forms

## 1. Session Header

- **Date:** 2026-06-01
- **Session Type:** Feature implementation (frontend)
- **Focus Area:** Wave 3 Sales Module — correctness fix for itemId UUID stamping
- **Status:** Complete — working tree dirty, awaiting user verification and commit
- **Session Objective:** Fix the critical correctness bug where sales doc line items stored
  `itemId = itemCode` (a string like "TOM-SEED") instead of the real UUID from
  `sale_item_finance_ext`. This caused JE handler to fail to resolve revenue + COGS
  accounts when chaining Quote → AR Invoice.

---

## 2. What We Accomplished

### Root Cause Fixed

`QuoteFormPage.tsx` lines 697–700 had:
```js
if (!watch(`lines.${index}.itemId`)) {
  setValue(`lines.${index}.itemId`, watch(`lines.${index}.itemCode`) || v);
}
```
This silently set `itemId = "TOM-SEED"` instead of the real UUID. The finance JE handler
queries `sale_item_finance_ext WHERE itemId='TOM-SEED'` and finds nothing — no revenue
account resolves, no COGS account resolves.

### New Component: SalesItemCombobox

`frontend/user-portal/src/components/sales/SalesItemCombobox.tsx` (new, ~370 lines)

- Mirrors `CustomerCombobox.tsx` structural pattern exactly
- Data source: `useSaleItemFinanceExtList(orgId)` filtered to `isSellable === true`
- Client-side filtering — entire list fetched once (small master data set, ~1–100 items)
- Dropdown shows `${itemCode}` + optional tax badge + `${itemName}`
- `onChange(SalesItemSelection | null)` stamps: `itemId` (UUID), `itemCode`, `itemName`, `salesTaxCode`
- Selected state → read-only chip with X clear button
- Unselected state → search input with live filtered dropdown
- `disabled` prop disables in from-X modes (item locked to source document)
- ARIA: role="combobox" + role="listbox" + keyboard nav (↓/↑/Enter/Escape)
- styled-components with `$` transient props throughout

### Forms Wired (7 of 7 line-item forms)

All use `<Controller name="lines.N.itemId">` pattern with `field.onChange` + `setValue`
for `itemCode`, `itemName`, and optionally `taxCodeId`:

| Form | File | From-X Lock Condition |
|------|------|----------------------|
| QuoteFormPage | `pages/sales/QuoteFormPage.tsx` | none (create/edit only) |
| SalesOrderFormPage | `pages/sales/SalesOrderFormPage.tsx` | `mode === 'from-quote'` |
| DeliveryFormPage | `pages/sales/DeliveryFormPage.tsx` | `isFromSO` |
| ARInvoiceFormPage | `pages/sales/ARInvoiceFormPage.tsx` | `isFromDelivery` |
| ReturnRequestFormPage | `pages/sales/ReturnRequestFormPage.tsx` | `isFromDelivery` |
| ReturnFormPage | `pages/sales/ReturnFormPage.tsx` | `isFromRR || isFromDN` |
| ArCreditNoteFormPage | `pages/sales/ArCreditNoteFormPage.tsx` | `customerLocked` (from-RTN or from-Invoice) |

**CustomerReceiptFormPage skipped** — confirmed its "lines" are invoice allocations
(`arInvoiceDocEntry`, `amountApplied`), not inventory line items. No change needed.

### Broken Fallback Removed

`QuoteFormPage.tsx` — the old `onChange` handler on the itemName input (lines 693–701)
with the `itemId = itemCode` fallback is gone, replaced by the Controller pattern.

### Design Decisions

- `Controller` owns `itemId` (the UUID field) — no duplicate `register()` on same name.
- `itemCode` and `itemName` registered as `<input type="hidden">` so Zod validation fires.
- Table headers collapsed: "Item Code" + "Item Name" → single "Item" column housing the combobox.
- `shouldValidate: true` on `setValue` calls so RHF re-evaluates on selection.
- `setValue` and `watch` added to `useForm` destructure in `ReturnRequestFormPage` (were missing).
- `Controller` added to `react-hook-form` import in 5 of the 7 form files.
