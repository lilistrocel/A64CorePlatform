### Foundation

- Created `salesApi.ts` — full AR Invoice API methods, all other Wave 3 docs stubbed with typed `NOT_IMPLEMENTED` stubs.
- Created `useArInvoices.ts` — TanStack Query hooks: `useArInvoices`, `useArInvoice`, `useCreateArInvoice`, `useCreateArInvoiceFromDelivery`, `useUpdateArInvoice`, `useDeleteArInvoice`, `useTransitionArInvoice`. Query key constants exported as `ariQueryKeys`.

### Routes (App.tsx)
Five new routes registered inside the protected block with explicit ordering to prevent `/new` being matched as a `:docId`:
- `/sales/ar-invoices` → `ARInvoicesPage`
- `/sales/ar-invoices/new` → `ARInvoiceFormPage`
- `/sales/ar-invoices/from-delivery/:deliveryDocId` → `ARInvoiceFormPage`
- `/sales/ar-invoices/:docId/edit` → `ARInvoiceFormPage`
- `/sales/ar-invoices/:docId` → `ARInvoiceDetailPage`

### AR Invoice Pages

**ARInvoicesPage** (~350 lines): Status filter chips (ALL / DRAFT / OPEN / CANCELLED), date range pickers, client-side search by doc number and customer name, paginated table (DocNumber, DocDate, Customer, DueDate, Total, Open Amount, Status badge), "+ New AR Invoice" primary button, row-click navigation to detail.

**ARInvoiceFormPage** (~700 lines): Three modes via `useParams` — new, edit (`:docId`), from-delivery (`:deliveryDocId`). Zod schema validates header and at minimum one line. `CustomerCombobox` via RHF `Controller`. `useFieldArray` for dynamic lines. `useTaxCodes` for tax code select per line with `FALLBACK_TAX_CODES` constant as safety net. `useMemo` computed totals watching `watch('lines')`. Successful submit navigates to detail page.

**ARInvoiceDetailPage** (~600 lines): Contextual action bar (DRAFT → Edit + Post + Delete; OPEN + super_admin → Cancel; otherwise read-only). InfoGrid (4-column header data). Lines table. Doc-chain card with links to base Delivery and downstream docs. `AttachmentList` with `docType="AR_INVOICE"`. `AuditHistoryModal`. Delete confirmation modal that does NOT close on overlay click (X button only per project rule).

## 3. Bugs / Issues Discovered

### TS6196: 'ARInvoice' declared but never used (FIXED)
- **File:** `ARInvoiceDetailPage.tsx:29`
- **Fix:** Removed `ARInvoice` from the import statement (type was imported but the component uses `useArInvoice` hook return value directly without re-typing it).

### TS6133: 'isNew' declared but never read (FIXED)
- **File:** `ARInvoiceFormPage.tsx:421`
- **Fix:** Deleted `const isNew = !isEdit && !isFromDelivery;` — the variable was computed correctly but never referenced in JSX or logic. `isEdit` and `isFromDelivery` are used directly where needed.

### ESLint: Stub function params flagged as unused (FIXED)
- **File:** `salesApi.ts:368–388`
- **Cause:** Stub functions like `getQuote(_id, _orgId)` use underscore-prefix convention but ESLint still flags them as unused.
- **Fix:** Wrapped stub section with `/* eslint-disable/enable @typescript-eslint/no-unused-vars */` block comment — appropriate since these are intentionally unimplemented stubs.

### ESLint: useMemo dependency on logical expression (FIXED)
- **File:** `ARInvoicesPage.tsx:363`
- **Cause:** `const invoices = data?.data ?? []` was declared outside the memo, but passed as a memo dependency — the logical expression `data?.data ?? []` creates a new array ref on each render, causing the memo to fire every render.
- **Fix:** Moved `const invoices = data?.data ?? []` inside the `useMemo` callback and changed the dependency from `[invoices, search]` to `[data, search]`.

### Backend gap: AR_INVOICE attachment endpoint not wired
- **Severity:** Low (graceful degradation)
- **Description:** `AttachmentDocType` was extended to include `'AR_INVOICE'` and `AttachmentList` renders correctly, but the backend `src/modules/sales/api/v1/attachments.py` (or equivalent) does not yet accept `AR_INVOICE` as a valid `doc_type`. The `AttachmentList` component handles 404 gracefully (shows empty state).
- **Action:** Tracked as T-200.x in BACKLOG.md — needs a follow-up task to wire the attachment endpoint for AR invoices.
