### New pages

- **`ReturnsV2Page.tsx`** — List page with status chips (All/Draft/Open/Cancelled),
  source-type chips (All/From RR/From DN), search input, paginated table. `SourceTag`
  styled component colored blue (RR) / yellow (DN) / gray (other) via `getSourceType()`
  helper reading `baseDocRef.docType`. "+ New Return Note" button → `/sales/returns-v2/new`.

- **`ReturnFormPage.tsx`** — 4-mode form detected via `useParams`:
  - **from-rr/:rrDocEntry** — fetches RR via `useReturnRequest`; pre-fills customer,
    companyCode, docDate, actualReturnDate, lines with `requestedQty - consumedQty`
    as defaulted returnedQty; maxQty hint shown; lines non-removable; customer locked;
    submits to `createReturnFromRR` (POST `/from-request/:rrDocEntry`).
  - **from-delivery/:dnDocEntry** — fetches DN via `useDelivery`; pre-fills customer,
    lines with `quantity - (returnedQty ?? 0)` defaults; maxQty hint shown; lines
    non-removable; customer locked; submits to `createReturnFromDelivery` (POST generic,
    client-side copy approach — DN has no server-side /from-delivery RTN endpoint).
  - **:docId/edit** — fetches existing RTN via `useReturn`; pre-fills all fields;
    `AttachmentList docType="RETURN"` shown; submits to `updateReturn`.
  - **new (blank)** — empty form; submits to `createReturn`.
  - Zod schema with `lineSchema` (warehouseId required) + `formSchema`. `useFieldArray`
    for lines with `Trash2` remove buttons (hidden in from-X modes). InfoBanner per mode.

- **`ReturnDetailPage.tsx`** — Detail page with:
  - 4-color `StatusBadge` (draft → slate, open → emerald, cancelled → red, default → gray).
  - Action bar: draft → Edit + Post + Delete; open → Issue Credit Note (Tooltip, T-200.8) +
    Cancel (super_admin only); cancelled → read-only.
  - Info grid: Customer, DocDate, ActualReturnDate, Status, CompanyCode, Notes.
  - Read-only lines table with TotalsRow (net + tax + gross).
  - Doc-chain card: Source resolves RR → `/sales/return-requests/:id`, DN → `/sales/deliveries/:id`.
    Credit Notes section (targetDocRefs). `resolveDocRoute()` helper.
  - AttachmentList with `docType="RETURN"`.
  - Delete confirm modal: X-button close ONLY (no overlay onClick — project rule).
  - NO Audit History button (Wave 3 rule).

## 3. Bugs / Issues Discovered

### ESLint — 7 errors in ReturnFormPage.tsx (fixed immediately)

| Line | Rule | Fix |
|------|------|-----|
| 332 | `no-unused-vars` | Removed `isNew` variable (declared but never referenced in render) |
| 394, 395, 396 | `no-constant-binary-expression` | `Number(x) ?? 0` → `Number(x) \|\| 0` (from-RR pre-fill block) |
| 486, 487, 488 | `no-constant-binary-expression` | Same fix in edit pre-fill block |

`Number()` never returns null/undefined — using `??` is always a no-op (ESLint correctly
flags it). Switched to `||` which also guards against NaN (0 fallback).

  generic `POST /returns-v2` endpoint with the DN as `baseDocRef`. This is intentional —
  there is no backend `/returns-v2/from-delivery` endpoint (verified). Disclosed in code
  comments on both the API function and the hook.
- **Hardening rules applied:**
  - `_RESPONSE_CONFIG` on RTN models: `src/modules/sales/models/returns.py`
  - `response_model_by_alias=True` on RTN routes: `src/modules/sales/api/v1/returns_v2.py`
  - Status literals are lowercase (`draft`, `open`, `cancelled`) throughout TS types
  - NO Audit History button on `ReturnDetailPage`
- **Hot reload:** The three new page files will be picked up automatically by Vite's HMR.
  The App.tsx route additions also hot-reload. No Docker restart, npm install, or
  migration is needed for these frontend changes.
- Backend hardening (models.py + returns_v2.py) requires API restart — already done and
  smoke-verified in this session.
