## What Was Accomplished

### Deliverable A — Attachment service routing fix

**File:** `src/modules/attachments/services/attachment_service.py`

- Added `_SALES_V2_COLLECTIONS` dict constant mapping each Wave 3 `AttachmentDocType` to its
  MongoDB v2 collection name (`ar_invoices_v2`, `quotes_v2`, `deliveries_v2`, etc.).
- Added `_SALES_MUTABLE_STATUS = "draft"` constant (sales docs are mutable only in draft).
- Refactored `_assert_document_exists_and_is_draft` into a dispatcher + two private methods:
  - `_assert_purchasing_document_is_draft`: queries `document_headers` with `docId`,
    `organizationId`, `docType`, `deletedAt: None` — mutable when status in `_MUTABLE_STATUSES` (`{"Draft"}`).
  - `_assert_sales_v2_document_is_draft`: queries the correct v2 collection with `docEntry`
    (not `docId`), `organizationId` (camelCase), no `deletedAt` filter — mutable when
    `status == "draft"` (lowercase).

**Tests:** Extended `tests/unit/test_attachments/test_attachment_service.py` with 13 new tests
covering all 8 sales doc types happy paths, immutable status, not-found, purchasing regression
guard, and soft-delete paths. Total test count: 40 (from 22).

### Deliverable B — Sales audit endpoint

**New file:** `src/modules/sales/api/v1/audit.py`

- `GET /api/v1/sales/audit?docType=<TYPE>&docEntry=<UUID>&organizationId=<UUID>`
- Dispatches to `<doctype>_v2_audit` Mongo collection (8 supported types via `_SALES_AUDIT_COLLECTIONS` dict).
- Requires `sales.view` permission.
- Returns `SalesAuditResponse { entries: SalesAuditEntry[], total: int }` with camelCase JSON
  aliases via `alias_generator=to_camel`.
- Supports both `userId` and `actorUserId` field names in raw Mongo docs via `_doc_to_entry`.
- 400 on unknown `docType`; 500 on MongoDB failure.
- Uses `datetime.now(tz=timezone.utc)` — not the deprecated `datetime.utcnow()`.

**Registration:** `src/modules/sales/api/v1/__init__.py` — router added at prefix `/audit`
with tag `Sales — Audit History`.

**Tests:** `src/modules/sales/tests/test_sales_audit.py` — 17 unit tests using inline
`_call_audit_handler` reproducer (avoids full FastAPI DI chain while still testing pure
business logic and model serialization).

## Bugs / Issues Discovered & Fixed

### 1. `datetime.utcnow()` deprecation

- **Severity:** Low (deprecation warning, Python 3.12+)
- **Location:** `src/modules/sales/api/v1/audit.py` — `_doc_to_entry` fallback timestamp
- **Root cause:** Initial draft used `datetime.utcnow()` which is deprecated in Python 3.12.
- **Fix:** Changed import to `from datetime import datetime, timezone` and used
  `datetime.now(tz=timezone.utc)` as the fallback.

### 2. Settings validation blocking audit test import

- **Severity:** High (all audit tests fail to collect)
- **Location:** `src/modules/sales/tests/conftest.py`
- **Root cause:** Importing `from src.modules.sales.api.v1.audit import ...` triggered
  `src/modules/sales/api/v1/__init__.py` → all routers → `middleware/auth.py` →
  `config/settings.py` → `Settings()` → pydantic-settings read env vars and raised
  "Extra inputs not permitted" for `ANTHROPIC_API_KEY`, `FINANCE_OUTBOX_ENABLED`, etc.
- **Fix:** Added module stubs in `conftest.py` for `src.modules.sales.config.settings`,
  `src.modules.sales.middleware.auth`, `src.modules.sales.middleware`,
  `src.modules.sales.services.database` before any sales API import.
