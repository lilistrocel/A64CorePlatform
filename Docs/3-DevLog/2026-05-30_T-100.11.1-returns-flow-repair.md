## Bugs / Issues Discovered

### Bug 1: `_FakeCollection` missing `find_one_and_update` (Category A — test fixture shortfall)

**Severity:** P0 — caused all 47 tests to fail with `AttributeError`
**Files:** `test_return_requests.py`, `test_returns.py`, `test_ar_credit_notes.py`

**Root cause:** All three new test files defined a `_FakeCollection` in-memory fake for Motor, but omitted `find_one_and_update`. The `next_doc_number()` function in `src/core/documents/doc_number.py` (line 156) calls `find_one_and_update` with `upsert=True, return_document=True` on the `doc_number_counters` collection to generate sequential document numbers like `RR-2026-0001`. Every test that creates a document triggers this path.

**Fix:** Added `find_one_and_update` method to `_FakeCollection` in all three test files. For `test_return_requests.py`, used the existing `_apply_update` helper. For `test_returns.py` and `test_ar_credit_notes.py`, created a new `_apply_update_simple` helper (the existing `update_one` in those files had complex embedded-line logic incompatible with the counter's flat `$set`/`$inc` writes):

```python
async def find_one_and_update(self, query, update, **kwargs):
    """Supports upsert=True for next_doc_number counter pattern."""
    upsert = kwargs.get("upsert", False)
    for doc in self._docs:
        if _matches(doc, query):
            _apply_update_simple(doc, update)
            return doc
    if upsert:
        new_doc: Dict[str, Any] = {}
        if "_id" in query:
            new_doc["_id"] = query["_id"]
        _apply_update_simple(new_doc, update)
        self._docs.append(new_doc)
        return new_doc
    return None
```

### Bug 2: OutboxWriter patches pointed at wrong module (Category A — test fixture shortfall)

**Severity:** P0 — caused all 9 tests in `test_returns.py` and 15 tests in `test_ar_credit_notes.py` that patched OutboxWriter to fail with `AttributeError: module has no attribute 'OutboxWriter'`
**Files:** `test_returns.py`, `test_ar_credit_notes.py`

**Root cause:** Both files patched `src.modules.sales.services.rtn_service.OutboxWriter` and `src.modules.sales.services.ar_credit_note_service.OutboxWriter` respectively. However, both services import `OutboxWriter` via a deferred local import inside the function body (not at module level), specifically to avoid triggering redis connection attempts at import time. Deferred local imports never become module-level attributes, so `patch()` on the module attribute always fails.

The correct canonical location is `src.modules.finance_bridge.outbox_writer.OutboxWriter.publish`. This works because `src/modules/sales/tests/conftest.py` stubs `src.core.cache.redis_cache` and `src.core.cache` at sys.modules level, allowing the `finance_bridge.outbox_writer` import chain to resolve cleanly during tests.

**Fix:** Changed all patch targets to the canonical location in both test files:

```python
# WRONG (was):
with patch("src.modules.sales.services.rtn_service.OutboxWriter", ...):

# CORRECT (now):
with patch(
    "src.modules.finance_bridge.outbox_writer.OutboxWriter.publish",
    new_callable=AsyncMock,
    return_value=str(uuid.uuid4()),
) as mock_publish:
```

For tests that needed to assert on what was published (e.g. `test_open_transition_emits_outbox`), switched from a custom `_mock_publish` capture function to `as mock_publish` on the context manager and then `mock_publish.assert_called_once()` + `mock_publish.call_args.kwargs`.

### Bug 3: `list_return_requests()` and `list_returns()` had wrong parameter name and wrong dict keys (Category B — real defect)

**Severity:** P1 — caused `TypeError: got an unexpected keyword argument 'page_size'` on all list tests
**Files:** `src/modules/sales/services/return_request_service.py`, `src/modules/sales/services/rtn_service.py`

**Root cause:** Both service functions used `size: int = 20` as the pagination parameter, but all tests called them with `page_size=2`. The return dicts used camelCase keys (`perPage`, `totalPages`) but tests asserted snake_case (`page_size`, `total_pages`).

**Fix:** Renamed `size` to `page_size` in both functions and updated the return dict keys to snake_case.

### Bug 4: `datetime.date` stored in MongoDB (Category B — real defect)

**Severity:** P0 — caused HTTP 500 `cannot encode object: datetime.date` on every document creation and update in the live stack
**Files:** `src/modules/sales/services/return_request_service.py`, `src/modules/sales/services/rtn_service.py`

**Root cause:** Both services wrote Pydantic `date` field values (from `payload.doc_date`, `payload.valid_until_date`, `payload.actual_return_date`) directly into MongoDB update dicts. Motor/PyMongo only encodes `datetime.datetime`, not bare `datetime.date`.

The pattern was already fixed in `ar_credit_note_service.py` (which had a `_to_dt()` helper). The other two services were missed in T-100.11.

**Fix:** Added `_to_dt()` helper to both services and wrapped all date field writes:

```python
def _to_dt(d: date) -> datetime:
    if isinstance(d, datetime):
        return d
    return datetime(d.year, d.month, d.day, 0, 0, 0, tzinfo=timezone.utc)
```

Applied in both `create_*` paths and `update_*` field_map dicts.

### Bug 5: `CurrentUser` missing `organizationId` (Category B — real defect)

**Severity:** P0 — caused HTTP 400 "organization_id is required" on every API call in the live stack
**File:** `src/modules/sales/middleware/auth.py`

**Root cause:** `CurrentUser.__init__()` did not accept or store an `organizationId` parameter. All API endpoints in the sales module call `_resolve_org_id()` which does `getattr(current_user, "organizationId", None)`. Because the attribute did not exist, `getattr` always returned `None`, and `_resolve_org_id()` raised HTTP 400.

This was not caught by unit tests because the unit tests mock or bypass the auth middleware. It was only visible in the live stack.

**Fix:** Added `from typing import Optional` import and `organizationId: Optional[str] = None` parameter to `CurrentUser.__init__()`. Updated `get_current_user()` to populate it from `user_doc.get("organizationId")`.

**Verification:** Both events confirmed in `finance_outbox` collection with correct `event_type` and `payload`. Ops-side state (inventory, ARI totals, RR consumedQty, DN returnedQty) all correct regardless of this gap.
